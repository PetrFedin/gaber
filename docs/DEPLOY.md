# GABER — запуск стенда одним контейнером

**PRODUCTION HOLD.** Образ предназначен для стенда и демонстрации с вымышленными данными. Реальные заказы, деньги и персональные данные клиентов в нём обрабатывать нельзя: нет банковской интеграции, допуска производства, резервного копирования и независимого ревью.

## Что внутри

Один процесс Node отдаёт собранный сайт (`dist`) и API (`/api/v1/*`). Образ собирается из корня репозитория (`Dockerfile`), в рабочем образе только серверные зависимости, запуск от пользователя `node`, проверка состояния по `/health`.

```sh
docker build -t gaber .
```

## Что нужно снаружи

1. **PostgreSQL 17** и две роли БД с минимальными правами (заказы под RLS и вход). Скрипт `server/dev/setup.mjs` показывает, какие права нужны, но создаёт вымышленных пользователей и запрещён в production. Для стенда применяйте миграции `server/migrations/001…009` вручную под DBA (`psql -v ON_ERROR_STOP=1 -f …` по порядку), роли и права выдаёт администратор базы.
2. **Организации и пользователи.** Фабрики и партнёры заводятся вне API: запись в `gaber_orders.factory_directory` и в `gaber_auth.users` (хеш argon2id, роль `partner` или `factory`, для фабрики `factory_id`). Публичная регистрация создаёт только клиентов.
3. **Секреты** только в окружении контейнера, не в образе и не в репозитории.

## Переменные окружения

| Переменная | Назначение |
| --- | --- |
| `GABER_ORDERS_DATABASE_URL` | Подключение роли заказов (RLS по tenant) |
| `GABER_AUTH_DATABASE_URL` | Подключение роли входа и сессий |
| `GABER_TENANT_ID` | Идентификатор tenant оператора платформы |
| `GABER_AUTH_ENC_KEY` | 32 байта в base64: шифрует секреты TOTP в базе. Без него MFA отвечает `MFA_NOT_CONFIGURED` |
| `ALLOWED_ORIGINS` | Источники, с которых разрешены запросы с cookie, через запятую (адрес сайта) |
| `GABER_STATIC_DIR` | Каталог сайта; в образе уже `/app/dist` |
| `HOST`, `PORT` | Адрес и порт (в образе `0.0.0.0:8788`) |
| `NODE_ENV=production` | Включает `Secure` у cookie и запрещает dev-флаги |

**Запрещено в production** (сервер откажется стартовать): `GABER_DEV_ASSUME_MFA`, `GABER_DEV_SIMULATE_EXTERNAL_AUTHORITY`.

## За обратным прокси

Cookie с флагом `Secure` работают только по HTTPS: терминируйте TLS на прокси и передавайте запросы контейнеру. Заголовки безопасности (`X-Frame-Options`, `nosniff`, `Referrer-Policy`, `Permissions-Policy`) контейнер ставит сам; строгий CSP, HSTS и ограничение числа запросов настраиваются на прокси. Ограничитель попыток входа и MFA хранится в базе (`gaber_auth.login_attempts`), но ключом служит адрес соединения: за прокси передавайте реальный адрес клиента, иначе все клиенты окажутся «одним адресом» (поддержка `trust proxy` не реализована).

## Проверка стенда

```sh
curl -s https://<адрес>/health          # {"status":"live",...}
curl -s https://<адрес>/api/v1/auth/me  # {"user":null,"server":{...}}
```

В ответе `/api/v1/auth/me` поле `server.devSimulatedAuthority` и `devMfaAssumed` должны быть `false`.

## Что не сделано

Автоматическое применение миграций, резервное копирование и восстановление базы, мониторинг и журналы в централизованном хранилище, ротация секретов и сессий, нагрузочные проверки, образ для нескольких экземпляров с общим ограничителем за прокси.
