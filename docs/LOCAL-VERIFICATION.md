# GABER — локальная проверка на Mac вместо GitHub Actions

Платные минуты GitHub Actions недоступны, и раньше все три job'а падали ещё до запуска шагов. Поэтому проверка выполняется на рабочем Mac скриптом `scripts/verify-local.sh`. Он повторяет job'ы CI и привязывает результат к точному SHA. Это локальное доказательство: оно **не заменяет независимое ревью** и не даёт допуска в production.

## Запуск

```sh
npm run gate          # полный шлюз
npm run gate:quick    # без Docker и браузера
bash scripts/verify-local.sh --allow-skip   # пропуски не считаются отказом
```

Нужны Node из `.nvmrc`, запущенный Docker (образ `postgres:17`) и для Chromium `npm i --no-save playwright && npx playwright install chromium`. Свободное место: образ PostgreSQL и сборка занимают порядка гигабайта.

## Что проверяется

| Шаг | Что делает |
|---|---|
| repository | `verify:repository`: инвентаризация исходников по Git-хешам и структура |
| node-tests, ui-tests | `test:node`, `test:ui` (jsdom, включая раздел «Заказы») |
| build | `vite build` |
| pg-migrations | одноразовый контейнер PostgreSQL 17 на порту 55490, миграции 001–009 и контракт RLS (`verify-postgres-staging.sh`) |
| pg-fixtures, http-e2e | HTTP → журнал → PostgreSQL для трёх ролей и двух tenant |
| auth-setup и четыре E2E | роли БД, вход, оплата и граница HOLD, dev-симулятор, MFA |
| browser | `scripts/browser-smoke.mjs` в настоящем Chromium: три роли, весь локальный цикл, переполнение на 375/768/1440 |

Контейнер создаётся с уникальным именем и случайным паролем и удаляется в конце, даже при ошибке. Ваши контейнеры (`gaber-pg`, `gaber-v04-pg`) не используются и не останавливаются.

## Результат

Запись пишется в `.local-verification/<sha>.json` (каталог в `.gitignore`) вместе с логами шагов. Шлюз возвращает ненулевой код, если: упал шаг, шаг пропущен (без `--allow-skip`) или в рабочем дереве есть незакоммиченные файлы. Строка `GATE PASSED для <sha>` печатается только при полном проходе на чистом дереве.

Ссылаясь на проверку в описании PR, указывайте SHA и дату прохода. Новый коммит требует нового прохода.

## Проверка перед push (по желанию)

```sh
git config core.hooksPath .githooks   # включает быстрый шлюз перед каждым git push
```

Хук запускает `gate:quick`. Отключение: `git config --unset core.hooksPath`.

## Ограничения

- Результат относится к одной машине и её окружению: версии Node, Docker и Chromium нужно фиксировать в записи (Node уже сохраняется).
- Время Chromium-шага зависит от нагрузки Mac: при холодном старте dev-сервера возможен выход за 30 секунд, тогда шаг повторяют на спокойной машине, а не подкручивают порог.
- Шлюз не заменяет ревью другим человеком, тест на проникновение и проверку на реальных устройствах.
