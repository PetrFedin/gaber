## Как восстановить идентичный исходный состав

Требуется авторизованный доступ к закрытому репозиторию, Git и Node.js. Команды запускаются из корня проекта; для точного повторения использовать **полный SHA** требуемого PR, а не автоматически изменяющееся имя ветки.

```bash
git clone git@github.com:PetrFedin/gaber.git
cd gaber
git fetch origin --prune
git switch --detach <FULL_SHA_FROM_PR_2>
git rev-parse HEAD
git status --porcelain
nvm install
nvm use
npm ci
npm run verify:source
npm test
npm run build
```

Ожидается пустой вывод `git status --porcelain` после checkout; `.nvmrc` фиксирует Node.js **24.22.1**, `package-lock.json` — точные версии npm-зависимостей. `npm ci` должен выполняться без исправления lockfile.

Инвентаризация `docs/evidence/source-inventory.json` фиксирует пути и Git blob SHA-1 всех отслеживаемых файлов, кроме самого манифеста. `npm run verify:source` проверяет наличие и точные байты файлов. При **намеренном** изменении файлов обновить манифест командой `npm run snapshot:source`, затем закоммитить вместе с изменённым кодом. Это контроль комплектности, **не** доказательство корректности функций или независимый аудит безопасности.

Воспроизводимость означает проверяемые исходники/зависимости/процедуру тестирования; равенство байтов собранного `dist/` не заявляется до отдельной проверки.

| Проверка | Текущий статус | Что требуется |
| --- | --- | --- |
| Единое Git-дерево | **Есть** (инженерная ветка) | Инвентаризация и один PR |

## Порядок интеграции

1. Не создавать новые рабочие ветки Габер. Весь актуальный код и новые изменения — в PR #2; PR #1 закрыть как `superseded` **только после сверки предков**.
2. Диагностировать GitHub Actions: доступность hosted runners/разрешения Actions/параметры лимитов (проверять по настоящим сообщениям GitHub). Зафиксировать runner, шаги и успешный полный цикл на **одном** коммите.
3. Провести независимый просмотр diff, проверку зависимостей, чувствительных данных и прав доступа; затем принять PR #2 в `main` **без обхода проверок**.
4. После merge сверить `main` с проверенным состоянием и повторить CI. `main` становится единственным авторитетным источником кода.
5. `PRODUCTION HOLD` снять лишь после отдельных PostgreSQL, server auth, E2E, финансовых, фабричных и визуальных gate. Слияние в `main` само по себе не разрешает продажи и производство.
