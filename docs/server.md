# Серверный слой GABER (первая версия)

Что это: небольшой сервер на Fastify и PostgreSQL. Заказ больше не живёт в localStorage, а клиент не получает себестоимость и нормы. **Все ставки, нормы и материалы по-прежнему демонстрационные, реальных данных фабрики в системе нет.**

**Выбор Fastify (а не Express):** встроенная проверка тела запроса по JSON-схеме (лишние поля отбрасываются) и `app.inject` для тестов без поднятия порта. Для маленького API с проверками на каждом маршруте это меньше кода и меньше зависимостей.

## Запуск

Нужны Node 22+ и Docker. Порт PostgreSQL по умолчанию `55481` (проверен свободным на момент работы; чужие контейнеры не трогаем, при занятости поменяйте `GABER_PG_PORT`).

```bash
cp .env.example .env          # файл .env не коммитится; пароль в нём только для локальной базы
npm run db:up                 # PostgreSQL 16 в Docker (контейнер gaber-pg)
npm run db:seed               # миграции + тестовые пользователи (только для разработки)
npm run server                # API на http://127.0.0.1:8787
npm run dev                   # сайт на http://127.0.0.1:4173, /api проксируется на сервер
```

Тестовые пользователи (менеджер, технолог, клиент) и их пароли лежат только в `server/seed-data.js`. Клиентов можно создавать и самим: «Войти» → «Создать аккаунт».

База для интеграционных тестов создаётся один раз:

```bash
docker exec gaber-pg psql -U gaber -c "CREATE DATABASE gaber_test"
npm test                      # TEST_DATABASE_URL берётся из .env
```

Без `TEST_DATABASE_URL` интеграционные тесты сервера честно помечаются как пропущенные (в CI поднимается PostgreSQL, и они выполняются).

## Что есть

- **Роли:** клиент, менеджер, технолог. Публичная регистрация создаёт только клиентов; сотрудников добавляют вне API (seed или SQL).
- **Вход:** почта и пароль (argon2id), серверные сессии в таблице `sessions` (в базе хранится SHA-256 токена), cookie `httpOnly`, `SameSite=Lax`, `Secure` в production. Ограничение попыток входа (8 за 10 минут на пару IP+почта, в памяти процесса). Изменяющие запросы с чужим заголовком `Origin` отклоняются.
- **Проекты:** конфигурация хранится неизменяемыми версиями (`project_versions`, триггер запрещает UPDATE и DELETE). Клиент видит только свои проекты; чужой проект отвечает 404.
- **Заявки:** `draft → requested → approved | changes → requested`. Каждый переход пишется в `request_events` (история решений). Комментарий видит клиент, внутренняя заметка — только персонал. Версию можно менять и проект удалять только в `draft` и `changes`.
- **Идемпотентность:** `POST /api/projects` требует заголовок `Idempotency-Key`. Повтор с тем же ключом и телом возвращает тот же ответ (`Idempotency-Replay: true`), с другим телом — 422. Параллельные запросы с одним ключом создают одну заявку (проверено тестом).
- **Расчёт:** `shared/domain.js` и `shared/costing.js` — общий код сервера и тестов. Сервер сам проверяет конфигурацию (`checkConfig` → `validate`) и считает цену, цифрам клиента не верит. Скидка до 30%; при марже ниже 35% предложение подтверждает только технолог.

## Граница видимости

| Данные | Гость | Клиент | Менеджер | Технолог |
| --- | --- | --- | --- | --- |
| Цена изделия (`/api/quote`, поле `price`) | да | да | да | да |
| Свои проекты, заявки, комментарии | — | да | да | да |
| Чужие заявки, себестоимость, маржа, строки калькуляции | нет | нет | да | да |
| Нормы и ставки (чтение, `#costing`) | нет | нет | да | да |
| Изменение норм | нет | нет | нет | да |

В клиентский код сайта расчёт и нормы не входят: тест проверяет, что `src/` не импортирует `shared/costing.js`, а в собранном бандле нет подписей и значений ставок. Закупочные цены тканей вынесены из публичного каталога во внутренний профиль.

## API

`POST /api/auth/register | login | logout`, `GET /api/auth/me`, `POST /api/quote`, `GET|POST /api/projects`, `GET|DELETE /api/projects/:id`, `POST /api/projects/:id/versions | submit`, `GET /api/factory/requests`, `POST /api/factory/requests/:id/decision`, `GET|PUT /api/internal/profile`, `POST /api/internal/estimate`. Ошибки приходят как `{error, message}`.

## Границы: что не сделано и не проверено

- Нет организаций, ролей дизайнера и финансов, совместной работы, комментариев по деталям, КП в PDF, уведомлений и CRM/ERP.
- Нет сброса пароля, подтверждения почты, двухфакторного входа. Ограничитель попыток входа работает в памяти одного процесса.
- Старые проекты из localStorage (`gaber.projects.v1`) не переносятся; остаётся только офлайн-черновик текущей конфигурации (`gaber.draft.v1`). Заявку без сервера отправить нельзя.
- Нет продакшен-развёртывания, TLS, резервного копирования, мониторинга и нагрузочных проверок. В production задайте `NODE_ENV=production`, `ALLOWED_ORIGINS`, отдельную базу и пароль; `server/seed.js` там отказывается запускаться.
- Раздача собранного фронтенда этим сервером не настроена: в разработке сайт проксирует `/api` через Vite.
- Ручная проверка прошла на локальном сервере в браузере встроенной панели (регистрация клиента, заявка, вход менеджером, себестоимость). Мобильные устройства и реальные браузеры, кроме одного, не проверялись.
- Данные демонстрационные: ставки и нормы нельзя считать производственными, пока фабрика их не подтвердит.
