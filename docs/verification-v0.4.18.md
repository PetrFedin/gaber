# GABER v0.4.18 — серверный журнал заказов

**Статус: Draft / Production HOLD.** Это реализация серверного слоя, не готовый SaaS/ERP и не работающая авторизация.

## Что сделано
- `server/orderJournalService.js` — атрибуция событий от серверной сессии, версия заказа, отпечаток запроса, цепочка SHA-256, контролируемое воспроизведение событий, идемпотентность.
- `server/postgresOrderRepository.js` — PostgreSQL SERIALIZABLE, явное ограничение tenant/order, FOR UPDATE, CAS головы журнала, повтор 40001/40P01, COMMIT перед подтверждением.
- `server/orderJournalWiring.js` — серверная композиция существующего reducer и admission, без HTTP API.
- `server/migrations/002_order_event_journal_hold.sql` — SQL-схема, первичные ключи, уникальные request_id, RLS/FORCE, append-only events, отсроченная проверка целостности head ↔ events.
- `tests/order-journal-v0418.test.js` — отдельные регрессии для нового сервиса.

## Достоверные результаты
В изолированном контейнере Node.js 22 локальный прототип сервиса/адаптера прошёл **17/17** тестов с имитацией БД: конкурирующие запросы, повторы, подмена событий, ошибки COMMIT, ограничения tenant, транзакции и откаты. Переданная в GitHub версия была упрощена по сравнению с локальным прототипом; поэтому результат 17/17 **нельзя считать результатом полного выполнения точного GitHub SHA**. Файлы повторно проверяются в GitHub.

## Критические ограничения
- Нет подключённого PostgreSQL 17, настоящих RLS-тестов, серверного HTTP API, авторизации и MFA.
- Таблицу `order_resources` должен наполнять только авторизованный сервис регистрации/назначения. Не принимать состав участников из браузера.
- Команды `start`, `complete`, `quality_pass`, `ship`, `deliver`, `accept_delivery` запрещены до интеграции независимых источников подтверждения.
- `record_payment` является лишь локально заявленной записью, не банковским поступлением.
- SQL-миграция не применялась на действующей базе. Нужна независимая проверка syntax/RLS/FOR UPDATE/триггеров, грантов и восстановления после аварии.
- Отсутствует настоящая интеграционная цепочка с клиентом, фабрикой, брендом, партнёром и владельцем.
